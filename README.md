# threaded_portscanner

Python 3.13 で導入された GIL フリービルド（Free-Threaded Python / PEP 703）を実際に触って、
「マルチスレッドが本当に並列で動くとはどういうことか」を自分の手で確かめるために作った実験用ポートスキャナです。
スキャナとしての完成度よりも、CPythonの並行処理モデルを理解する題材として書いたコードです。

## 作った経緯・検証したかったこと

- 長年CPythonのマルチスレッドは「GILのせいでCPUバウンドな処理は並列化されない」と言われてきましたが、Free-Threadedビルドでそれがどう変わるのかを、自分で計測して体感したいと考えました。
- ポートスキャンはネットワークI/O待ちが挟まるとはいえ、大量のスレッドを同時に起動・実行させる負荷試験として手頃だったため題材に選びました。
- `threading` モジュールで128本のスレッドを起動し、各スレッドが `65536 / nthreads` 個ずつポートを担当して `socket.connect_ex()` によるTCPコネクトスキャンを行う、というシンプルな構成にしています。
- 通常のCPython（GILあり）ではスレッドがGILを奪い合い実質的に直列化されますが、GILフリービルドで実行すると各スレッドが真に並列に動作し、全体の所要時間が短縮されることを確認できます。
- 各ポートの開閉状態はあえてプログラム側では判定・出力していません（`connect_ex` の戻り値も破棄）。今回の主目的は「並列度」と「所要時間」の検証であり、実用的なスキャン結果は別途Wiresharkで確認する設計にしています。

## 使用技術

- Python 3.13 (Free-Threaded build / `python3.13t`)
- 標準ライブラリのみ（`threading`, `time`, `socket`） — 依存パッケージなし
- Wireshark（パケットキャプチャによる疎通確認）

## 動作要件

- Python 3.13 以降の Free-Threaded ビルド（`python3.13t` や `--disable-gil` でビルドしたインタプリタ、python.org配布の "free-threaded" インストーラなど）
  - 通常のGIL付きPythonでも動作はしますが、その場合スレッドが並列実行されないため、本スクリプトの検証目的（GILフリーの効果確認）が成立しません。
- 標準ライブラリのみ使用（`threading`, `time`, `socket`）。追加パッケージのインストールは不要です。

## 使い方

1. `main.py` 内の `ip` にスキャン対象のIPアドレスを設定します（デフォルトは空文字のため、実行前に必ず編集してください）。
2. 実行します。

```
python3.13t main.py
```

3. スレッドを起動してから join が完了するまでの時間（秒）が標準出力に表示されます。

## 疎通確認について（Wiresharkの利用）

このスクリプトは各ポートへの接続結果（開いている/閉じている等）を一切出力しません。そのため、実際にどのポートへ接続要求が送られ、対象ホストからどのような応答（SYN-ACK / RST など）が返ってきたかを確認したい場合は、Wireshark などのパケットキャプチャツールを別途起動し、送受信されるTCPパケットを直接観測してください。

## 今後の改善点（自己レビュー）

実装を振り返って、次に手を入れるならここだと考えている点です。

- `_.join()` がループの最後に生成した1スレッドしか待機していないバグがあります。本来は生成した全スレッドをリストに保持し、それぞれ `join()` する必要があります。計測時間の正確性にも影響するため、次の改善で最優先に直したい点です。
- 各ポートのスキャン結果（開放/閉鎖）を内部で判定・記録していないため、スキャナ単体では実用になりません。`connect_ex` の戻り値を見てキュー等に結果を集約し、最終的に一覧出力する機能を追加したいです。
- `nthreads` が `65536` を割り切れない場合に末尾のポートが漏れる、`tout=0.0` で環境によっては即タイムアウトするなど、境界値・例外まわりの作り込みが甘い部分があります。
- スレッド数や対象IPが起動時の固定値になっているため、CLI引数（`argparse`）化して使い勝手を上げたいです。
- 本格的に検証を深めるなら、Free-Threadedビルドと通常ビルドで同一条件のベンチマークを取り、所要時間の差をグラフ等で可視化してみたいと考えています。

## 使用上の注意

- 学習・検証目的の実験的なコードであり、実運用のポートスキャナとして必要な機能（結果集計、エラーハンドリング等）は備えていません。
- 短時間に大量のTCP接続を送出します。許可を得ていない第三者のホスト・ネットワークに対しては実行せず、自身が管理する環境、または明示的に許可を得た環境でのみ使用してください。
